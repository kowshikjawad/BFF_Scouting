# ShonarTalent AI Constitution

## Core Principles

### I. Evidence before presentation
Every named player MUST come from maintained reference data or an identified data source.
Missing real-player facts and tactical metrics MUST remain unknown. Explicitly authorized synthetic
datasets MUST use reserved IDs, fictional profiles and visible provenance; they MUST NOT alter real
records or mix into real-player analytics. Stock images MUST NOT impersonate players.
Screening results MUST distinguish software assessment from official association clearance.

### II. Complete scouting workflows
Search, inspect, save, assess and export MUST have working end-to-end paths. Every asynchronous
view MUST have loading, empty, failure and recovery states. No decorative controls may ship.

### III. Minimal and accessible design
Use semantic controls, readable typography, restrained green accents, visible focus states,
keyboard navigation, and responsive layouts from 360px. Assets MUST have documented licenses.

### IV. Contract correctness
Public schemas MUST preserve stored metrics and nullable facts. Inputs MUST have explicit bounds.
Partial ingestion MUST preserve previously known values and recover after transaction failures.

### V. Verification and maintainability
Meaningful regression tests MUST cover API behavior and core browser journeys. Build and lint MUST
pass. PDFs MUST be checked for page count and visually reviewed. Documentation MUST state verified
limits, especially source coverage and deployment dependencies.

## Constraints
Retain React/Vite/TypeScript, FastAPI and SQLite. This release is an unauthenticated scouting
workspace for trusted deployment; public multi-user collaboration and live paid feeds are outside
scope. Preserve the existing data and OpenSpec history. Use Spec Kit for new delivery specifications.

## Development Workflow
Audit existing behavior, specify acceptance criteria, resolve assumptions, plan changes, create
ordered tasks, implement, then reconcile verification evidence against the specification.

## Governance
This constitution governs new work. Amendments require a documented reason and semantic version
change; implementation must report any exceptions. User direction takes precedence over process.
